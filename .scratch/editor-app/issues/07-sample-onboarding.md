# 07 — Sample-document onboarding + first-run

Status: resolved
Blocked by: editor-app/02, editor-app/04

First visit (local flag): auto-create a beautiful sample Document and open it — multi-page showcase: title page feel, headings, callout-style GFM Alert, table, code block with theme, inline + display math, mermaid diagram, page frame + footer page numbers, so the preview wows in two seconds. Top of editor: dismissible welcome strip — "Start blank" / "This is a sample — edit or clear it". Once dismissed (or "Start blank" chosen), never auto-load again (IndexedDB flag). Second-run: open most recent document, or Library if none.

**Accepts**: fresh profile → sample renders >1 page within ~2s; dismiss persists; returning users land in their last document.

## Comments

**Implementation** (2026-09-07):

- `apps/web/src/documents/sample.md` + `sample.ts` — the showcase document, kept as a plain markdown file imported with Vite `?raw` (editable as text, prettier-formatted). Sections split by `///`: centered title page (single H1 + `centerH1`), GFM NOTE/TIP/WARNING alerts, table, themed ```ts fence (Shiki), inline + display math (KaTeX — formulas deliberately avoid `\,` and other punctuation escapes, which markdown-it would eat), a mermaid flowchart, and a page that shows the frame + footer furniture. `sampleSettings()` = default preset plus `centerH1`, accent page frame, and footer text beside the page numbers.
- `apps/web/src/documents/db.ts` — DB v2 adds an out-of-line-keyed `meta` store (`getMeta`/`putMeta`) for app-level flags. The `onboarding` record (`OnboardingMeta`: `sampleDocId` + `dismissed`) is written when the sample is first seeded; its **presence** gates seeding, so the sample is created exactly once and profiles that predate the feature (docs but no meta) never get one. `dismissed` governs only the welcome strip + re-seeding: the sample stays a normal library document, so "second-run: open most recent" can legitimately reopen it (typically edited). Edge ruling: a pre-feature profile that deleted *all* documents is indistinguishable from a fresh profile and gets the sample once — accepted, it's their first run of the new build.
- `apps/web/src/documents/store.ts` — `init()` seeds the sample on `!meta && docs.length === 0` (replacing the old blank-doc seed), exposes `sampleDocId`/`sampleDismissed`, plus `dismissSample()` and `startBlankDocument()` (dismiss, then create blank — the strip's "Start blank" invariant lives in the store, not the component).
- `apps/web/src/shell/WelcomeStrip.tsx` — the dismissible strip above the editor (visible iff the active document is the sample and not dismissed); "Start blank" + × both persist dismissal; the sample document itself stays in the Library.
- `apps/web/src/shell/AppShell.tsx` — mounts the strip in the editor pane and auto-opens the Library when ready with zero documents (the ticket's "or Library if none").
- `apps/web/src/canvas/mermaid.ts` — the `RenderMermaidHook` ticket 04 left as a handoff: lazy `import('mermaid')` (separate bundle chunk, loaded only when a mermaid fence first renders — verified lazy in the production build output), `initialize` once, SVG cache keyed by source (every keystroke re-runs the pipeline; ops/05's planned cache partially pre-delivered, unbounded Map — revisit if diagrams are many/large). Wired into **both** pipeline call sites (`PaperCanvas`, `clientExport.buildExportDocument`) so preview and print render diagrams identically (ADR-0003).
