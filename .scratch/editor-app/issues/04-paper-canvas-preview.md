# 04 — Paper Canvas (live paginated preview)

Status: resolved
Blocked by: editor-app/01, engine-port/04, engine-port/05, engine-port/06, engine-port/07

The core UX: run the engine pipeline (markdown → paginate → layouts) and render pages into the Paper Canvas — one shadow-DOM per page using the plugin's proven approach (adopted stylesheets, background → banners → header → content → footer → frame layering ported from `drawPreview`). Debounced auto-render (400ms) + manual Ctrl/Cmd+Enter. Floating zoom pill (35–100%, fit-width button), page labels, loading shimmer, RTL `dir` support, in-page anchor click → scroll to target page. Render loop guarded by token (cancel stale renders). Large-doc soft warning >100 pages (toast, "render anyway").

**Accepts**: sample doc renders multi-page pages pixel-consistent with export HTML (same docCSS source); zoom, labels, dark-mode chrome with white paper.

## Comments

Implemented 2026-09-06 (commit 85e8395).

- `apps/web/src/canvas/pipeline.ts` — `runDocumentPipeline(markdown, settings, {title, renderMermaid?})` composes the engine run the plugin's preview used: normalize LF → `applyAutoBreaks` (inserts `///` before H1/H2 per settings, fence/indent-aware, no break at doc start or before an existing marker) → `splitMarkdownSections` → per-section `renderMarkdown` → `paginateEl` → concatenated `buildPageLayouts`. Returns `{layouts, docCSS, isRTL, geometry}`: isRTL is decided once from the raw markdown and baked into the docCSS pagination measured against. A blank document yields one empty page (matches `paginateEl`'s own `[[]]` contract; the canvas and export both need ≥1 page). Also exports `collectAssetRefs` (markdown `asset://` refs + the three settings image refs, deduped — over-warming is one cheap IDB read).
- `apps/web/src/canvas/pageBuilder.ts` — one open shadow root per page; adopted sheets are `[katex layout rules, docCSS]` (math first, mirroring the export `<style>` order), built once per render and shared across pages. Layer order/geometry/inline styles byte-identical to `buildExportHTML`: the layer style strings are **core exports** (`bgImageLayerStyle`, `bannerStyle`, `headerBandStyle`, `footerBandStyle`, plus `buildHFInnerHTML` moved to css-builder) consumed by both builders, so preview/print parity is by construction, not copy-paste — the export golden test stayed byte-identical through the extraction. `data-pm-layer` attributes tag each layer (canvas-internal debug/test hook, no rendering effect). Page nodes are appended (consumed, not cloned) — a layout renders once. Host carries `transform-origin: 0 0` so canvas zoom scaling stays aligned.
- `apps/web/src/canvas/PaperCanvas.tsx` — debounced 400ms auto-render on markdown/settings/activeId; manual render via the component **ref** (`useImperativeHandle` exposing `{renderNow, setScrollFraction}` — React 19 ref-as-prop; AppShell wires Ctrl/Cmd+Enter and editor scroll sync through it, both halves pre-tested in EditorPane's and the canvas's suites). Render token bumped per run and checked after every await; doc-switch/unmount cleanup bumps it too, clears pages immediately, disposes the asset resolver (blob URLs released), and re-arms the large-doc guard. Pages are imperative DOM (engine-finished subtrees; React owns only the chrome): slots = frame wrapper (zoom-scaled, ambient shadow) + "Page N of M" label + shadow host at true page pixels. Scroll position preserved across re-renders; editor scroll fraction maps onto canvas scrollTop one-way. In-page anchors: delegated click reads `nativeEvent.composedPath()[0]` (shadow retargeting), resolves the heading-id → page-index map built at mount, `preventDefault`s and scrolls to the slot. Zoom pill −/+/⤢, 35–100%, fit-width = (canvasWidth − 2×24px gutter)/pageWidth. Shimmer (skeleton page, `animate-pulse`) shows whenever no pages are mounted — first load and doc switches. >100 pages: render pauses with a `role="status"` toast ("Render anyway" acknowledges for the document; × dismisses until the next render attempt; guard re-arms on doc switch or when the count drops back ≤100).
- KaTeX: `@perfectmarkd/core/katex.css` plain-imported (Vite hashes the fonts, registers them document-wide — `@font-face` applies inside shadow trees) and `?raw`-imported, sliced from the first `.katex{` rule (font-face block stripped) for adoption into page shadow roots. Vitest needed explicit aliases for both subpath forms (`@perfectmarkd/core/katex.css` + `?raw` → katex's own dist css) because the core source alias prefix-matches and swallows them.
- Mermaid: the pipeline forwards a `renderMermaid` hook but no app code supplies one yet — mermaid fences render as plain code blocks, identically in preview and export. Install + wire the hook in ticket 07 (sample doc needs it); Client Export inherits it through this same pipeline.
