# 06 — Client Export via print pipeline

Status: resolved
Blocked by: editor-app/04, engine-port/07

Main Export button = Client Export (ADR-0002): build `exportHTML` via the engine, write it into a hidden iframe, call `iframe.contentWindow.print()`. Before the first print per session, show a one-time hint ("Choose 'Save as PDF' in the dialog — quality is identical to a downloaded PDF"). Ensure `print-color-adjust: exact`, `@page` size, and no app UI in the print output. Browser detection: Firefox/Safari get a "best results in Chrome/Edge" notice. Dropdown menu item "Print…" is the same flow (the dialog is inherent). Disable button during render; busy state.

**Accepts**: exported print output matches Paper Canvas layout (spot-check manual + iframe-content structural test); hint shows once; no app chrome leaks into print.

## Comments

**Implementation** (2026-09-06):

- `apps/web/src/export/clientExport.ts` — the two halves of ADR-0002 plus the flow's environment probes:
  - `buildExportDocument(markdown, settings, title)` runs the *same* engine pipeline as the Paper Canvas (`runDocumentPipeline`) and feeds the layouts to core's `buildExportHTML`, so print output matches the preview by construction (same geometry, doc CSS, RTL decision). Assets resolve through `createAssetResolver(db, 'data-uri')` (ticket 08's contract): warmup, then markdown-embedded `img[src^="asset://"]` are swapped to data: URIs on the page nodes (unresolvable refs drop the image, matching the banner/background behavior), banner/background layers resolve inside `buildExportHTML`.
  - Math ships as the **full** KaTeX stylesheet via a new `?inline` import (`KATEX_EXPORT_CSS` in canvas/katex-css.ts): the export iframe is its own document, so fonts must register inside it (the preview's shadow trees ride the app's document-level `@font-face`). Vite's `?inline` rewrites the font URLs to origin-absolute assets, which resolve from the srcdoc frame (it inherits the app's base URL). Tests alias `?inline` to raw text — vitest externalizes node_modules CSS to `''` even through `?raw`/`?inline` queries, hence `test.css: true` in vitest.config.ts.
  - `printViaHiddenIframe(html)`: off-screen-but-rendered iframe (`display:none` frames don't print reliably), `aria-hidden`, `srcdoc` with an injected `data-pm-print-ready` sentinel; readiness = polling for the sentinel inside the frame, **not** the iframe load event (in real browsers it fires early for about:blank, and jsdom never parses srcdoc at all). Then `document.fonts.ready` (fresh budget — parse must not starve it), `focus()`, `print()`, frame removed in `finally` (print blocks until the dialog closes, so the frame dies right after). `setPrintLoadTimeoutForTests` shrinks the deadline; jsdom takes the deadline path every time.
  - `printQualityBrowser()` (Firefox / Safari-not-Chromium UA sniff) and the hint flag (`sessionStorage`, key `perfectmarkd:print-hint-shown`, try/catch-guarded).
- `apps/web/src/export/useClientExport.ts` — the phase machine: `idle → building → (first print this session? → awaiting-hint) → printing → idle`. Hint sits *between* build and print because the browser's print dialog is modal — anything shown after `print()` is invisible. Browser notice: inside the hint dialog on first use; on later Firefox/Safari exports a toast with a 2 s read delay before the dialog opens over it. Errors (build or print) log and surface as an "Export failed" toast; `busyRef` guards double-clicks.
- `apps/web/src/export/ExportSplitButton.tsx` — the top bar's `⬇ Export ▾` split button, self-contained: main click = Client Export, chevron opens a `role="menu"` whose "Print…" item runs the same flow (dialog inherent, per ticket); busy = spinner + "Exporting…" + `aria-busy` + both halves disabled; outside-pointer/Escape dismiss the menu; the hint dialog and toasts mount here so TopBar stays unaware of the flow. Disabled also when the store has no active document (`canExport`).

**Gap noticed, not fixed here (belongs to tickets 04/08):** the Paper Canvas preview never resolves markdown-embedded `asset://` images — the blob-url resolver warms them but nothing rewrites `img[src]` in the preview's page nodes, so pasted images render broken in the canvas while this ticket's export embeds them correctly. Client Export's `img` swap (or the equivalent in `mountPageSlots`) should be back-ported to the canvas; flagged for a follow-up ticket rather than folded into this one.
