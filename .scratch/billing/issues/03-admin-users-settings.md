# 03 — Admin panel: users + settings

Status: resolved
Blocked by: billing/02

**Users**: search by email, detail view (plan, expiry, quota usage, Orders history), actions: grant/extend/revoke Entitlement, comp quota, manual password reset (sets a temp password — no email infra), delete account (GDPR-ish: removes user + history files, anonymizes Orders). **Settings**: wallet addresses per coin, plan prices, plan page caps, quota limits, LTC rate source — all in `settings_kv`, editable in-panel (wallet change without redeploy), audit-logged. Guard: changing a wallet address shows a prominent warning.

**Accepts**: user admin actions apply immediately (gates re-evaluate on next fetch); settings changes live without redeploy; audit entries written.

## Comments

Implemented 2026-09-11 (commits `c7d0080` + review fixes).

- **Users** (`apps/server/src/admin/users.ts`, mounted at `/api/admin/users` behind billing/02's gate): `GET /users?query=` searches email substrings (SQLite LIKE is case-insensitive for ASCII; `%`/`_` are escaped via `ESCAPE '\'` so a search containing wildcards stays literal), newest first, 100-row cap for the single operator. `GET /users/:id` is the detail view: plan + expiry, this period's quota usage, and the full Order history reusing `adminOrderView` so the panel can't drift from the Verification queue. Usage = `{ period, used, comps, allowance }` where allowance is the plan's monthly quota **while the Entitlement is active**, plus comps — comping works for free accounts too (granting exports without a plan).
- **Actions**: `POST /:id/entitlement` grants/extends by hand — plan required, then the exact same `parseGrant` (extracted to `admin/grant.ts` and shared with Order Verification) and `expiryForGrant` stacking math: durations extend a still-active expiry (Jan 31 + 1mo → Feb 28), custom dates run to the end of that UTC day. `DELETE /:id/entitlement` revokes. `POST /:id/quota/comp` adds extra allowance to the current period (`export_usage.comps`, new migration 0003 column); negative amounts retract, floored at zero — read, floor check, and write all inside one transaction so concurrent comps can't lose updates. `POST /:id/password` generates a 16-char temp password (returned once; only its hash is stored) and revokes every session. `DELETE /:id` is GDPR-ish deletion: user + sessions + entitlement + usage + history rows cascade away; Orders are **anonymized in place** (migration 0003 made `orders.user_id` nullable with ON DELETE SET NULL, and the user's free-text `note` is cleared — amounts, txid, and the Admin's decision survive as the financial record); history files are removed after commit via an injectable `removeStoredFile` hook (default: best-effort unlink of absolute paths — server/03 owns the real storage layout). Every action writes its audit entry in the same transaction (`entitlement.grant`, `entitlement.revoke`, `quota.comp`, `user.password_reset`, `user.delete`; new `user` target type). Guards: the Admin cannot reset their own password or delete their own signed-in account; the deleted user's email is never written to the audit trail.
- **Settings** (`admin/settings-routes.ts`, `/api/admin/settings`): `GET` returns wallets, prices, the new `limits` (page caps + monthly quotas per plan, seeded pro 300/300 · premium 1000/1000), and the LTC rate. `PUT /:key` updates one key at a time — wallets, prices, limits, ltcRateUsdt — validated by the same parsers `db/settings.ts` readers use (`parseWalletAddresses`/`parsePlanPrices`/`parsePlanLimits`/`parseLtcRate`, now exported), so anything the panel writes is something the app reads; prices/limits must be positive (prices of 0 would make Orders free). Each PUT audit-logs `settings.update` with before/after. Clearing the LTC rate deletes the key (values are NOT NULL), which disables LTC payments — the seeded state. A wallet change takes effect on Order creation without redeploy (verified by test), as do price changes. **Interpretation note**: "LTC rate source" is implemented as the admin-maintained rate that Order creation captures (the setting *is* the source); a feed/URL would be new machinery no ticket or ADR asks for, and PLAN.md's volatility mitigation is the captured-rate mechanism itself.
- **Web** (`apps/web/src/admin/`): `/admin` now has four tabs — Users, Verification, Settings, Audit log. `UsersPanel` is search → list (plan/expiry, `used/allowance (period)`, comps, joined date) → `UserDetail` with the Entitlement card (grant/extend via `GrantEntitlementDialog` with plan toggle + stacking-aware preview reusing `previewExpiry`, revoke confirm), the usage card (`CompQuotaDialog`, current-period only), the Order history, and the account card (`ResetPasswordDialog` shows the generated temp password exactly once with a copy button; `DeleteAccountDialog` requires typing the account's email). `SettingsPanel` renders four independently-saved sections sharing one `useSectionSave` save loop; **the wallet guard is a prominent danger banner** that appears the moment any address differs from the saved one. Anonymized Orders stay in the Verification queue labelled "(deleted account)" and can be rejected but never verified (409 — there is no account to grant an Entitlement to).
- **Deliberately left out, with reasons**: a LTC feed/URL (see interpretation note); automatic history-file path resolution (server/03 defines the storage layout; the hook is the seam); per-row usage batching and pagination in the users list (single-operator scale); session-invalidating the *Admin's* view of a reset user beyond the immediate refresh (nothing else to invalidate).
- **Review findings folded in**: comp read-modify-write moved inside the transaction (lost-update race); revoke 409 message reworded (the check is row-existence, not "active"); settings routes use the injectable clock; grant/revoke response views reuse the action's instant so the usage period can't straddle UTC midnight; `PaymentMethod` imported from `billing/api` instead of re-declared; settings section save loop extracted to `useSectionSave`.

Web 29 new (panels, detail, all five dialogs, four settings sections, admin tabs) — full web file 470. Suite 791 green; typecheck, eslint, prettier clean.
