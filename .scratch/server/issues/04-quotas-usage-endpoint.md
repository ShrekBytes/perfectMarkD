# 04 — Quota accounting + usage endpoint

Status: resolved
Blocked by: server/03

Monthly usage per user (`export_usage` keyed by YYYY-MM, lazy reset on first use), plan quota lookup (300/1000) from settings, `GET /api/me` returning {plan, expires_at, quota: {used, limit}, is_admin}. Apps/web top bar shows the quota chip for logged-in paid users; over-quota exports rejected with typed error → upgrade prompt. Burst accounting separate from monthly quota.

**Accepts**: usage increments only on successful export; resets on period change; chip displays correctly; over-quota → 402-style typed error.

## Comments

Implemented 2026-09-11/12 (commits `e46c64e` + review fixes).

- **Shared quota math** (`apps/server/src/quota.ts`, new): the module owns everything `export_usage` — `usagePeriod` (UTC `YYYY-MM`; moved here from admin/users.ts so the quota module isn't reaching into admin), `incrementExportUsage` (moved from export/queue.ts; the worker still calls it only when a render finishes, so usage increments **only on successful export**), `isEntitlementActive` (a type predicate; an Entitlement expiring exactly now counts as expired), and `quotaState` — used, comps, and the limit: plan `quotaMonthly` **plus comps** while active, comps alone otherwise. The monthly reset is lazy by construction: rows are keyed by period, so a new month simply has no row yet and last month's counts can never leak (tested).
- **`GET /api/me`** (`apps/server/src/me.ts`, mounted at `/api/me`): 401 signed out; otherwise `{email, isAdmin, plan, expiresAt, quota: {used, limit}}` (camelCase per the codebase's other API views). The payload is the single source of truth for the client's gates; billing/04 extends it with feature flags. Deliberate contract: `plan`/`expiresAt` describe the **active** Entitlement — an expired row reports both null so the client re-locks with no second endpoint; the lapse date, if a future notice needs it, lives in Order history.
- **Enforcement** (`export/routes.ts`): over-quota enqueue → **402 `{error, code: 'quota_exceeded'}`**, checked before the burst window and before the payload is read, so a rejection burns nothing (no burst slot, no job row — asserted). Gate reconciliation (code-review finding): comps are granted to planless accounts (billing/03: "comping grants exports without a plan") and `/api/me` + the admin panel display them as allowance — so the route now allows a comped user **without** an active plan to spend comps: `used >= limit` yields 402 only with an active plan behind it, else 403 `entitlement_required`. Planless jobs snapshot `plan: 'free'` in `export_jobs` (plain text column, no migration): normal queue priority (only `premium` jumps), and the smallest paid page cap via the new `pageCapFor` (db/settings.ts) used at both the enqueue-time payload validation and the worker's post-render re-check.
- **One source of truth**: admin/users.ts's usage view now delegates to `quotaState` (dropping its inline copy), so the admin panel, `/api/me`, and enforcement cannot drift. The export route reads the clock once per request (a second `now()` could straddle a UTC midnight and flip the period — the same hazard admin/users.ts documents).
- **Web** (`apps/web`): `auth/api.ts` `me()` now consumes `/api/me`; the account store splits the payload into `user` (identity — unchanged shape, all existing consumers untouched) and a new `entitlement` slice, and gains `refresh()` (re-checks even when ready; a failed refresh keeps the current user on screen instead of flashing signed-out). `signedIn()` kicks a background refresh because login/register responses carry identity only. `shell/QuotaChip.tsx` renders `used/limit` (tabular-nums, danger styling + tooltip when exhausted) between the theme toggle and the Export button, hidden for signed-out and planless users. `POST /api/export`'s typed error codes are ready for billing/04's upgrade prompts.
- **Deliberately left out, with reasons**: calling `refresh()` after exports/verification — there is no web-side Server Export path yet (billing/04 replaces the dropdown's "coming soon" and owns the "gates open within one me refresh" acceptance); retiring `GET /api/auth/me` — it stays as server/02's identity contract until billing/04 consolidates on `/api/me`; renaming admin's `allowance` to `limit` — billing/03's published API shape, now backed by the same `quotaState` so no drift is possible.

Web 12 new/updated (account store split + refresh + failed-refresh + signed-in refresh; QuotaChip rendering/hidden/exhausted states; /api/me client contract; UpgradeFlow's fetch mock answers by URL).
