# 03 — Server Export pipeline (Playwright worker)

Status: resolved
Blocked by: server/01, editor-app/06

`POST /api/export` (auth): validate payload ≤ 50 MB + page caps by plan → enqueue job (SQLite queue table; payload held in memory of the API process). Implement a **stub plan guard** here (reject anything without an active entitlement) — billing/04 replaces it with real entitlement checks and quota enforcement, so this ticket does not wait on billing. In-process worker (concurrency 2, configurable): launch Playwright Chromium → load `<origin>/export` route → inject document + settings + assets (postMessage from the route's bootstrap; assets as data: URIs) → run the same engine pipeline → `Page.pdf()` (preferCSSPageSize for custom sizes) → `injectPDFOutline` → stream PDF back → delete payload. Premium jobs jump the queue; burst limiter (max N concurrent/minute per user). Errors surface as typed job failures. `/export` route: no chrome, `noindex`, renders via the exact Client Export document builder.

**Accepts**: end-to-end export returns a PDF whose text/pages match the Paper Canvas; quota decrement; payload deleted (test asserts); queue visible in DB.

## Comments

Implemented 2026-09-11 (commits `344c9ab` + `1e18ac1` review fixes).

- **Enqueue** (`apps/server/src/export/routes.ts`, mounted at `/api/export`): `POST /` requires a session, applies the **stub plan guard** (an active, unexpired Entitlement row — 403 `{error, code: 'entitlement_required'}`; billing/04 replaces it with real quota enforcement), then validates the payload (`export/payload.ts`): title (default `Untitled`, capped 200 chars), non-empty markdown, settings merged over core defaults and repaired by the engine's own `validate()` (same function the editor uses before persist), positive-integer `pageCount` ≤ the plan's page cap, and `assets` as `ref → data:` URIs (≤ 200). The 50 MB hard cap is a Hono `bodyLimit` on the sub-app (413 `payload_too_large`). The **burst limiter** (`max N/rolling 60s per user`, env `EXPORT_BURST_PER_MINUTE`, default 10) counts only requests that actually enqueue — malformed/over-cap payloads never burn a slot — and prunes expired windows on touch. Success returns **202** with the queued job view; the row lands in the new `export_jobs` table (migration `0004`) with the plan snapshotted at enqueue, so queue state, priority inputs, and typed outcomes are all durable and inspectable.
- **Worker** (`export/worker.ts`): in-process, event-driven (no timers when idle), `concurrency` default 2 (`EXPORT_CONCURRENCY`). Claiming is `claimNextExportJob` — premium first, FIFO within class, the UPDATE re-checks `queued` so a job can never be double-claimed. The render seam is injected; the default (`export/render.ts`) lazily imports playwright and launches one Chromium per process (first render, never at app construction), one context per job. Boot recovery fails every non-terminal row with `worker_restart` — a restart loses in-memory payloads, so silently re-queuing would hang forever. **Payloads are deleted the moment a render settles** (success or failure — `PayloadStore.take` is the one deletion point, asserted by tests); success stores the PDF bytes in memory, increments `export_usage` for the UTC period (the ticket's quota decrement; enforcement is billing/04), and marks the row `done` with the page count.
- **Render** (ADR-0003): Chromium loads `<origin>/export`, waits for the page's `__pmdExportReady`, posts the payload via `window.postMessage`, and the page runs `renderServerExportDocument` — the **exact Client Export pipeline** (`runDocumentPipeline` + asset-swap + `buildExportHTML`, with the mermaid hook, minus IndexedDB since assets arrive as data URIs) — paints the export document into the main frame (so Page.pdf prints it), waits for webfonts, and reports `{pageCount, outline}` through Playwright's `exposeFunction`. Then `Page.pdf({preferCSSPageSize, printBackground})` → core's `injectPDFOutline`. The whole render has a deadline (`EXPORT_RENDER_TIMEOUT_MS`, default 120 s); timeouts and page errors surface as typed codes (`render_timeout`, `render_failed`; `page_cap_exceeded` when the rendered count exceeds the plan cap — defense in depth behind the enqueue-time check).
- **Polling + download**: `GET /api/export/jobs/:id` (owner-only; a foreign job is 404, matching Orders) and `GET /api/export/jobs/:id/pdf` (409 before done, 410 `pdf_gone` after a restart since results are memory-only, else the PDF with `application/pdf` + attachment disposition). Enqueue-path errors carry a `code` field (`entitlement_required`, `burst_limit`, `payload_too_large`) for billing/04's upgrade prompts.
- **Web** (`apps/web/src/export/`): the hidden `/export` route (router + `App.tsx`) renders `ExportPage` — no chrome, runtime `noindex` meta, blank for humans — and delegates to `protocol.ts`, the wire contract's page side. Server and page share only field names by design (the server validates independently; `render.e2e.test.ts` drives both ends together, which is the drift guard).
- **Tests**: server 25 new (payload validation; claim order, premium jump, claim re-check, finish/fail/stale recovery, usage upsert, memory stores; worker flows — payload deletion, typed failures, concurrency cap, missing-payload, premium priority; API — gate matrix, enqueue→render→poll→PDF, foreign-job 404s, 409-before-done, burst limit, usage counting, unmounted-when-unconfigured). Web 8 new (protocol painting/outline/assets/failure; ExportPage handshake incl. origin+type filtering and noindex lifecycle). Plus a **real-Chromium e2e** (`playwright.vitest.config.ts`, CI step after the golden suite): fixture page mounts the actual bundled `protocol.ts` behind a local HTTP server with KaTeX fonts, and the acceptance runs for real — queued job → 2-page PDF with the document title in metadata and an Outlines dict, payload deleted, and a stuck page failing as `render_timeout`. Suite 831 green; typecheck, eslint clean; two-axis review findings folded in.
- **Deliberately left out, with reasons**: disk storage / encryption / history endpoints (server/05 — PDFs are memory-only until then; a restart makes finished PDFs 410); real quota enforcement (billing/04 — stub guard as the ticket instructs); `X-Robots-Tag` header for `/export` (a header is static-serving territory — server/06 should set it when it serves the SPA; the runtime meta tag is what a SPA can do alone); PDF text-extraction assertions in the e2e (needs a new dependency; text-level equality is the golden suite's job — the e2e pins the wiring: page count, title, outline through the real wire).
