# 05: `/ai` — ask, review, apply

**What to build:** A paying user pauses mid-sentence in the editor, types `/ai`, and a popup opens at their cursor showing what will be rewritten and how big it is. They describe the change, press Enter, and after a working state a dialog shows the proposal as a diff they can read, uncheck, accept or reject. Accept changes the Document as one undo step, focus returns to their place, and one AI Action is counted. Nothing reaches the Document without that acceptance. A Free Tier visitor typing the same thing gets the upsell instead, a user who has turned AI off gets no command at all, and an instance with no provider configured shows nothing anywhere. The first AI Action per account states where the text is going, and the Privacy page already says it.

**Spec:** `.scratch/ai-transforms/spec.md` (trigger rules, the review surface, the AI route contract, gate precedence, AI Access, and the promises that must change).

**Blocked by:** 03 (provider config, the provider seam, the instance's AI state), 04 (the estimator, scope resolution, and anchored edits).

**Status:** ready-for-human

- [x] A hint appears for `/a` and `/s` only, accepting with Tab, Enter, or a click; a bare `/` shows nothing; `/aix` and other continuations trigger nothing; matching is case-insensitive and only at a line start or after whitespace, never inside inline or fenced code; pasted text and programmatic edits trigger nothing.
- [x] `/ai` plus a space opens the popup at the caret with the trigger text removed; Esc restores exactly what was removed, leaving the Document byte-identical; Enter submits, Shift+Enter adds a line, and Cancel aborts a running request.
- [x] The popup states the resolved scope and its size against the cap, and its own state when unavailable: not configured (no command at all), not entitled (upsell copy plus one line that AI Actions send the submitted text to an external AI provider, opening the pricing modal), AI off (no command in the editor), allowance spent (the count, the period, and the reset date), provider unavailable (a plain message with Retry, naming nothing about the provider).
- [x] The review dialog shows a graphite diff with `+`/`−` marks, three lines of context, a change count, and a "show all" control; each change is independently checkable and checked by default; Accept applies the checked changes as one undoable edit through the normal document-update path; Reject leaves the Document untouched; Retry and Edit prompt are both available and each submission is a fresh AI Action.
- [x] A truncated, empty, or unusable reply is refused with a plain message and a smaller-scope suggestion, is never offered as a proposal, and consumes no allowance; a proposal whose target text changed underneath it cannot be accepted and says why.
- [x] The allowance and the switch behave as specified: AI Actions counted only when a proposal is offered, in a calendar-month period of their own, separate from Server Export Quota in both directions and in every surface; the Account page carries the remaining count and the AI Access switch beside plan and Quota, and the first-use disclosure is recorded on the account, once.
- [x] The Privacy page and the product principles document are updated so that what leaves the browser, when, and what is never stored are stated plainly, and no claim contradicts them.
- [x] Tests: the trigger rules and popup states as component tests; the route's gate order, metering, and error codes against a fake provider; the review dialog's accept, reject, and partial accept as component tests; and an end-to-end browser pass typing `/ai`, reviewing, accepting, and asserting the Document's new text with one undo step back.

## Comments

- Implemented (ai-transforms/05). The server half (`apps/server/src/ai/routes.ts`, `prompts.ts`, plus `state.ts`'s `incrementAiUsage`) landed first and was already sound; this pass wired the client half and closed the gaps that left it unreachable.
- The editor surface: `apps/web/src/editor/ai-trigger.ts` is the CodeMirror extension (typed input only, so a paste or a programmatic edit triggers nothing), `apps/web/src/ai/trigger.ts` holds the pure matching rules, `AiHintPopover` is the `/a` `/s` discovery hint, `AiPromptPopover` the prompt panel, `AiReviewDialog` the review surface, and `useAiCommand` the controller that owns the popup and review state and applies an accepted proposal through the editor's one-dispatch path (so autosave, cross-tab broadcast, and undo behave as for a hand edit — one acceptance is one undo step). `EditorPane` mounts all three and anchors them to the caret via `apps/web/src/ai/anchor.ts`.
- Four defects found and fixed while wiring, each of which the tests now pin:
  - The extension fired on Space/Tab/Enter regardless of the gate, so with AI Access off (or an instance with no provider) `/ai ` was silently deleted from the Document with nothing to show for it. The handlers now carry `enabled()`, read per keystroke, and every binding declines when the commands do not exist — the space is inserted and the trigger stays as prose.
  - `beginRequest` read `popup` from its closure, so Retry — which starts a request with the popup closed — recorded no review at all. The anchor is now passed in, and Retry keeps the dialog open with its own inline error instead of bouncing the user back to the popup.
  - The review dialog's Enter-to-accept was a handler on the content div, but the modal panel is what takes focus on open and a keydown on an ancestor never reaches a descendant. It is now a document-level listener, matching `useEscapeLayer`.
  - `anchoredContext` kept the partial boundary line on each side of an anchor, rendering a blank line above and below every change instead of three lines of real context.
- The Account page gains `AiSection` (remaining Actions and the reset date beside Server Export Quota, the AI Access switch on the reused `ToggleRow`, the upsell for a Free Tier visitor) and renders nothing on an instance with no provider configured. The Privacy page states plainly what leaves the browser, that nothing is stored by us, and that provider retention is the provider's; its "your browser talks to no one else" line now names AI Actions as the deliberate exception. `apps/web/PRODUCT.md` and `PLAN.md`'s privacy posture already carried the narrowed claim.
- Verified: `pnpm vitest run apps/web/src/ai apps/web/src/editor/ai-command.test.tsx apps/web/src/account/AiSection.test.tsx apps/server/src/ai` (63 new tests: the trigger rules, the popup's states, the dialog's accept/reject/partial accept and every disabled reason, the editor integration, and the route's gates, metering, and error codes against a fake provider), the full `pnpm test` (112 files, 1,370 tests), `pnpm typecheck`, `pnpm lint`, and `pnpm build`.
- Verified in a real browser: `apps/web/e2e/ai-command.spec.ts` (7 tests, passing) types `/ai`, watches the hint appear, opens the popup on the space with the trigger consumed, submits, reviews the proposal, accepts, asserts the Document's new text, and asserts one undo step back to the original — plus reject, Esc-restores, a refused truncated reply, the Free Tier upsell opening the pricing modal, and both unavailable states. The rest of the browser suite passes except `shell-compact.spec.ts`'s "crosses to the three-pane row exactly at the panes' minimum width", which fails identically on a clean checkout of `923e0db` (24px of shell overflow) and is not caused by this work.
- `pnpm format:check` still fails repo-wide on files that are already unformatted on a clean checkout; every file this ticket created or edited is prettier-clean.

- A two-axis review (standards + spec) then found four more, all fixed:
  - `paneRef` was declared and read but never attached to an element, so `caretAnchorStyle` always took its null-pane fallback and both panels rendered at the editor pane's top-left corner instead of at the caret. The pane now carries the ref and a `data-testid`, and the e2e asserts the popup is neither at the pane's origin nor hanging out of its box.
  - Anchoring only clamped the top edge, so a caret near the pane's bottom opened a panel that overflowed it. `caretAnchorStyle` now flips the panel above the caret when the space below is too small and returns a `maxHeight` capped to whichever side it chose — the panel's height is only known after it renders, so the cap is what keeps it inside on the first paint rather than after a measured correction. Its rules (below, flip, left clamp, unmeasurable fallback, never-negative cap) are unit-tested in `anchor.test.ts`.
  - The review dialog's document-level Enter listener checked the disabled reason but not `busy`, so Enter applied the proposal being replaced while a Retry was in flight.
  - The exhausted state stated the period and the reset date but not the count the spec asks for. The `ai` block now also reports `allowance` (the plan's monthly AI Allowance) alongside `remaining`, so the popup says "You have used all 100 AI Actions for September 2026. They reset on 2026-10-01." and the Account page says "93 of 100 left this month". The scope readout also moved above the gate branches, so the popup states what would be sent in every state, available or not.
- Review follow-ups deliberately not taken: the `{removed, at}` trigger anchor and the `command === 'stylesheet'` branch recur in a few places and could each become a shared type or map, and `apps/web/src/ai` and `apps/web/src/editor` import types from each other in both directions. Both are judgement calls with no behaviour attached, so they were left for a change that needs them.
- `apps/web/src/docs/docs.md` also claimed the self-hosted instance "makes no third-party requests; nothing in it phones home" without qualification, which the AI feature contradicts once an Admin configures a provider. It now names AI as absent-until-configured and adds a Privacy FAQ entry for AI Actions, so no shipped page contradicts the Privacy page.
