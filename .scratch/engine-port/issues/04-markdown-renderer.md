# 04 — Markdown renderer pipeline (markdown-it + KaTeX + Shiki + mermaid)

Status: resolved
Blocked by: engine-port/01, engine-port/03

New `packages/core/src/render.ts` replacing the plugin's `markdown.ts`. markdown-it with: linkify, GFM tables/strikethrough, tasklists, footnotes, markdown-it-front-matter (parse + expose; strip per setting), GFM Alerts (container plugin producing `markdown-alert markdown-alert-note` structures), attrs off, typographer on. Math: KaTeX auto-render for `$…$`/`$$…$$` with display mode; bundle KaTeX CSS+fonts. Code: Shiki async highlighting with theme from settings (fall back `github-light`); mermaid fenced blocks rendered to SVG (client provides the mermaid instance — core accepts an optional `renderMermaid` hook to stay env-agnostic). Post-processing ported from `postProcessRenderedHTML`: heading slug IDs (dedup), anchor rewrite, copy-button strip, style/script cleanup (keep SVG-embedded styles). RTL detection ported as-is. Async API returning clean HTML string + frontmatter object.

**Accepts**: sample markdown (headings, table, task list, footnotes, alert, math, code, mermaid, RTL text) renders correct clean HTML; unit tests per feature.

## Comments

Implemented 2026-09-05 (this commit).

- `packages/core/src/render.ts`: `renderMarkdown(md, options) → { html, frontmatter }` plus the ported text helpers (`normalizeMarkdown`, `splitMarkdownSections`, `isRTLContent` verbatim) and `postProcessRenderedHTML` (heading slug IDs with dedup, fragment-anchor rewrite incl. `data-href`, copy-button strip, style/script cleanup keeping SVG-embedded styles). Obsidian-only cleanups (`.external-link`, callout fold expansion) dropped with the renderer that produced them — matches issue 03 dropping their CSS defenses.
- Pipeline: markdown-it 15 (html on, linkify on, typographer on, attrs never added; default preset gives GFM tables + strikethrough) with footnote, task-lists (disabled checkboxes, print-safe), github-alerts (emits `markdown-alert markdown-alert-*` + octicon title — exactly the structure issue 03's CSS targets), and front-matter plugins.
- Shiki 4 async highlighting: fence rule swaps per-render placeholder divs for `codeToHtml` output after the DOM parse (markdown-it's renderer is sync). Theme from `settings.codeTheme` with `github-light` fallback, `'none'` → escaped plain block, unknown language → plain block. Legacy alias map `atom-one-light→one-light`, `atom-one-dark→one-dark-pro` (persisted old-plugin settings values; shiki renamed the themes). KaTeX auto-render `$…$`/`$$…$$` (display mode for `$$`), `svg` added to ignoredTags; parse uses a `<!DOCTYPE html>` wrapper because KaTeX refuses quirks-mode documents (bare-fragment `DOMParser` output is quirks in browsers and jsdom). Mermaid via optional `renderMermaid` hook; missing or failing hook falls back to the plain code block (the bounded-wait equivalent). Fence-slot swap replaces all placeholder matches so literal `data-pm-pending` text in source can't strand a real fence.
- Design decision (not specced): with `hideFrontmatter: false` the parsed frontmatter renders as a simple escaped key/value table at the top — the standalone equivalent of Obsidian's properties view; the object is exposed in the result either way. Invalid YAML: stripped, exposed as null.
- KaTeX CSS+fonts bundled via tsup `onSuccess` copy to `dist/katex.css` + `dist/fonts/`, exported as `@perfectmarkd/core/katex.css`; runtime deps left external in tsup so shiki's grammar set isn't duplicated into dist.
- `vendor-types.d.ts`: ambient shims for `markdown-it-task-lists`, `katex/contrib/auto-render`, and `markdown-it-footnote` (its @types package pins the retired `markdown-it/lib` types and conflicts with markdown-it 15's bundled types; `markdown-it-front-matter`'s own typings had the same conflict, retyped at the import site).
