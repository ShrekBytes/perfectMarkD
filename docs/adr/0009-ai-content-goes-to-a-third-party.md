# AI Actions send Document content to a third party — paid, disclosed at the point of use, and switchable off

An AI Action necessarily ships the user's own text to an external AI provider: the targeted markdown plus the Document as context for `/ai`, and the Custom Stylesheet plus the styling reference for `/ss`. That contradicts the launch privacy posture, which claimed no third-party requests at all. The posture changes rather than the claim being quietly dropped: `PRODUCT.md` and the Privacy page are rewritten to say what leaves the browser, when, and what is never done with it; the first AI Action says where the text is going; the Account page carries the switch to turn AI off; and while it is off the commands do not exist for that user. AI Actions are paid and metered per plan, so no anonymous visitor can spend the operator's credits.

We store nothing: the prompt, the document text, and the result are not persisted, not written to logs, and never touch Export History. The provider's own retention is the provider's, and the Privacy page says so instead of implying otherwise. AI is on by default, and that is not the same as sending anything by default: a request exists only because the user submitted one, so the submit *is* the choice — which puts the whole obligation on disclosure at that moment. Anything that sends text without a submit, or that hides where it went, would break this decision. Rejected alternatives: running a model on the same VPS (a GPU box costs more than the entire product's hosting budget, and CPU inference is too slow to sit behind a typing-speed popup); an on-device model in the browser (a multi-hundred-megabyte download and quality well below what the feature promises); and gating AI behind a switch to find and flip before the feature works at all — friction that buys no privacy the submit does not already provide.
