# AI runs behind the API server, and users never learn what it is

The AI features — `/ai` (rewrite markdown) and `/ss` (edit the Custom Stylesheet) — reach the provider through the API server, never from the browser. The Admin configures the endpoint, the model, and the reasoning effort in the admin panel; the API key is environment configuration only. Nothing user-facing ever names the provider or the model: upstream error bodies are logged and surfaced to the Admin, while the user gets a plain "the AI is unavailable right now" and a retry.

Three things forced this. A key shipped to the browser is a key given away — it cannot be recalled, and it cannot be metered or revoked per user. Metering has to be server-side, or the allowance is decoration that anyone with devtools can remove. And the product promise the AI has to fit is "you do not have to think about which AI this is"; that only holds if the choice is the operator's, not the user's.

Trade-offs accepted: every AI Action costs a server round trip on top of the model's own latency; the app now depends on a third party being reachable; and a Self-Hosted Instance has no AI at all until its operator supplies a key, which is the right default — an instance should not silently gain a third-party dependency it never chose. The key living in the environment rather than in the settings table means rotating it needs a restart, accepted because a secret in the database is exposed by every settings read and every backup. Rejected alternatives: browser-direct calls with a client-side key, and bring-your-own-key for users (which pushes a provider decision onto the people least able to make it, and breaks the invisibility the feature is supposed to have).
