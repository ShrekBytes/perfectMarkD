# Email leaves to Resend — addresses and one-time links, never Document content

Email verification and password reset require a mailer, and the launch privacy posture ("no third-party requests at all") cannot survive that: the provider necessarily receives the recipient address and the message body, which contains a one-time link. The posture is restated rather than quietly dropped, exactly as ADR-0009 did for AI: **no Document content ever leaves the browser.** What an email carries is an address the user gave us and a link to a sign-in page — nothing rendered, nothing edited, nothing from Export History.

Resend's HTTP API is the provider, with `RESEND_API_KEY` in the environment: the API key belongs to the deployment, not to a setting, matching how the AI provider key is treated. The mailer is not switchable off (ADR-0009's AI switch has no analogue here): password reset that can be turned off is not password reset, and sign-in is blocked until the email is verified, so the feature is load-bearing for account access. The Privacy page is updated to say what leaves the browser, when, and what is never done with it — Resend's own retention is Resend's, and the page says so instead of implying otherwise.

Rejected alternatives: SMTP from the VPS (IP reputation from a home/Cloudflare-Tunnel deployment lands verification mail in spam, which for a verify-to-sign-in flow is an account lockout); a provider-abstraction setting in the admin panel (a second configurable third-party integration to document and support, for a need one env var already meets); and no-op "verification" that never sends mail (the honest version of which is the status quo this decision replaces).
